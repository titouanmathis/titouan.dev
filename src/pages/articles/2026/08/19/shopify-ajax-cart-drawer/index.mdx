A cart drawer confirms an add-to-cart in a panel that slides in, without leaving the page. It also has the most moving parts: an accessible overlay, a focus trap, a scroll lock, and a cart that stays in sync. [`@studiometa/ui`](https://ui.studiometa.dev) gives you the drawer and the AJAX wiring as components, on top of [`@studiometa/js-toolkit`](https://js-toolkit.studiometa.dev).

Add a product below. The item posts to the cart, the drawer refreshes and slides in, and the count updates:

import demoTwig from './demo.twig?raw';
import demoTs from './demo.ts?raw';

  client:visible
  html={demoTwig}
  script={demoTs}
  height="380px"></UiPlayground>

## The drawer is a Panel

[`Panel`](https://ui.studiometa.dev/components/Panel/) is a slide-in panel that extends the library's `Modal`, so it inherits the accessibility work: a focus trap while open, close on <kbd>Escape</kbd>, an overlay click to dismiss, and a background scroll lock. It is a JavaScript component: it enhances whatever markup carries the right refs, so you render that markup in Liquid. `@studiometa/ui` also ships a `Panel.twig` template for Twig-based stacks, but a Shopify theme is Liquid, so you write the structure out (once, in a snippet).

`Panel` needs six refs: `open[]` (triggers), `close[]` (dismiss controls), `modal` (the dialog root, hidden until open), `overlay`, `container` (the sliding panel), and `content`. The `data-option-position` attribute drives which edge it slides from.

```html
<div data-component="Panel" data-option-position="right">
  <button data-ref="open[]">Cart (<span id="cart-count">0</span>)</button>

  <div data-ref="modal" role="dialog" aria-modal="true" aria-hidden="true"
    class="z-50 fixed inset-0" style="opacity:0;pointer-events:none;visibility:hidden">
    <div data-ref="overlay" class="-z-10 absolute inset-0 bg-black/40 transition duration-500 opacity-0"></div>
    <div class="z-10 absolute inset-y-0 right-0 flex items-center pointer-events-none">
      <div data-ref="container" class="h-full transform transition duration-500 translate-x-full pointer-events-auto">
        <button data-ref="close[]">Close</button>
        <div data-ref="content">
          <div id="cart-drawer">Your cart is empty.</div>
        </div>
      </div>
    </div>
  </div>
</div>
```

The `open[]` and `close[]` buttons are wired to open and close automatically, so the trigger works on its own. `data-option-position="right"` makes it a right-edge drawer, and the component animates the `container` in from that edge. The `scrollLock` option is on by default; set `data-option-scroll-lock="false"` on the panel if you ever need to opt out. (The full demo markup fills in the Tailwind classes; this is the load-bearing structure.)

## Add to cart with the Cart AJAX API

Shopify's [Cart AJAX API](https://shopify.dev/docs/api/ajax/reference/cart) adds items with `POST /cart/add.js`. A drawer relies on **bundled section rendering**: pass a `sections` parameter and the JSON response includes a `sections` key with the rendered HTML of each section you asked for, in one round trip. So a single add-to-cart request can return both the added line and the re-rendered drawer.

The add-to-cart form is a `Fetch` component. It posts the variant `id` and `quantity`, plus the sections to refresh, and its `response` option pulls the section HTML out of the JSON:

```liquid
<form action="{{ routes.cart_add_url }}" method="post"
  data-component="Fetch"
  data-option-response="response.json().then((data) => Object.values(data.sections).filter(Boolean).join(''))">
  <input type="hidden" name="id" value="{{ variant.id }}">
  <input type="hidden" name="quantity" value="1">
  <input type="hidden" name="sections" value="cart-drawer,cart-count">
  <button type="submit">Add to cart</button>
</form>
```

`Fetch` swaps the returned `#cart-drawer` and `#cart-count` by `id`, exactly as in the [Section Rendering article](/articles/2026/07/29/shopify-section-rendering-api-example/). The `id` for the added variant comes from the [variant selector](/articles/2026/08/12/shopify-variant-selector/): its job is to keep that hidden input pointed at the right variant.

## Opening the drawer on add

The last piece connects the two components. `Fetch` emits a bubbling `fetch-update` event once the DOM is swapped, so an [`Action`](https://ui.studiometa.dev/components/Action/) on a shared parent opens the `Panel` and drives the loader:

```html
<div
  data-component="Action"
  data-on:fetch-before="Transition(#cart-loader) -> target.enter()"
  data-on:fetch-after="Transition(#cart-loader) -> target.leave()"
  data-on:fetch-update="Panel(#cart-panel) -> target.open()">
  <!-- header with the Panel, and the product grid with add-to-cart forms -->
</div>
```

Because `Fetch`'s events bubble, one `Action` on the wrapper handles every add-to-cart form on the page. `Panel(#cart-panel) -> target.open()` calls the drawer's `open()` method — the `(#cart-panel)` selector scopes it to the drawer, so no other `Panel` on the page opens — and `open()` is a no-op if it is already open, so adding a second item just refreshes the contents.

Register the four components this drawer uses once, in your theme's main script:

```js twoslash
// @noErrors
import { registerComponent } from '@studiometa/js-toolkit';
import { Action, Fetch, Panel, Transition } from '@studiometa/ui';

[Action, Fetch, Panel, Transition].forEach(registerComponent);
```

## How the demo simulates it

The playground has no cart, so the demo mocks `POST /cart/add.js`: it keeps an in-memory cart, and returns what Shopify returns from that endpoint, the added line item plus a `sections` object holding the rendered `cart-drawer` and `cart-count` HTML. The added line is the item itself, with fields like `id`, `key`, `quantity` and `title`; a top-level `items` array is what `/cart.js` returns, not `/cart/add.js`.

```js twoslash
// @noErrors
window.fetch = async (input, init) => {
  const url = new URL(
    typeof input === 'string' ? input : input instanceof URL ? input.href : input.url,
    'http://localhost',
  );
  if (url.pathname.endsWith('/cart/add.js')) {
    const id = init.body instanceof FormData ? String(init.body.get('id')) : '101';
    /* update the in-memory cart, then return the added line item… */
    return new Response(
      JSON.stringify({
        id, quantity: 1, title: 'Cap',
        // …plus a `sections` object because the request carried a `sections` param.
        sections: { 'cart-drawer': drawerSection(), 'cart-count': countSection() },
      }),
      { headers: { 'content-type': 'application/json' } },
    );
  }
  return realFetch(input, init);
};
```

**Swap the mock for your store:** delete the `window.fetch` block. The form already posts to `/cart/add.js` with the `sections` parameter, which Shopify answers with real bundled sections, so the same markup drives the real cart. Use locale-aware URLs on a live theme: `{{ routes.cart_add_url }}` in Liquid, or `window.Shopify.routes.root + 'cart/add.js'` in JavaScript. You can point the section rendering at a specific page with a `sections_url` parameter (for example `/cart`) if the drawer markup only exists there.
